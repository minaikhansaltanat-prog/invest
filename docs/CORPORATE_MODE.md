# CORPORATE_MODE: қарапайым корпоративтік сайт және қарапайым әкімші панелі

Бұл құжат `corporate-lite` тармағына арналған. Портал бір кодтан екі режимде жұмыс істейді: `PORTAL_MODE=corporate` (әдепкі) және `PORTAL_MODE=full` (инвестициялық порталдың толық нұсқасы). Ештеңе жойылған жоқ: инвестициялық код, жинақтар, миграциялар, тесттер және кабинет орнында, corporate режимінде тек көрінбейді.
Кім оқиды: әзірлеуші және сайтты жүргізетін қызметкер.

## 1. Режимді қалай ауыстыру

Режим `PORTAL_MODE` айнымалысынан оқылады, оны бір ғана файл оқиды: [src/lib/mode.ts](../src/lib/mode.ts). Айнымалы жоқ немесе белгісіз болса, `corporate`. Тек `full` деген мән толық нұсқаны қосады (регистрге қарамайды).

| Жағдай | Команда |
| --- | --- |
| Corporate, әзірлеу | `npm run dev` |
| Full, әзірлеу | `npm run dev:full` |
| Өндіріс (Docker) | `.env` ішінде `PORTAL_MODE=corporate` немесе `full`, содан кейін `docker compose -f docker-compose.prod.yml --env-file .env up -d` |
| Тесттер | corporate: `npm run test:e2e`, full: `npm run test:e2e:full` |

Режим өзгерсе, серверді қайта іске қосыңыз (config серверді іске қосқанда оқылады). Схема режимге тәуелсіз: миграция қажет емес, режимді ауыстыру деректерді өзгертпейді.

## 2. Corporate режимінде не жасырылады

**Сайт маршруттары (404):**
- `/account` (тіркелу, кіру, кабинет, деректер бөлмесі): `/{тіл}/account`, `/account/login`, `/account/register`, `/account/dataroom/*`.
- `/investors` және барлық ішкі беттері (қытай, Парсы шығанағы, Еуропа мен Азия, климат, анықтамалық, өтініш формасы).
- `/projects` және барлық ішкі беттері: каталог, жоба деңгейлері, жобаны ұсыну, жеке жоба беттері.
- `/results` (нәтиже ашықтығы: төрт сома, бұл инвестициялық KPI).
- `/membership/apply` (мүшелікке өтініш) және `/membership/registry` (мүшелер тізілімі).
- `/styleguide`: тек corporate өндірісінде (әзірлеуде ашық).

**API (404, `{"error":"not-found"}`):** `/api/portal/*` ішінен тек `forms/contact`, `altcha`, `2fa` және `logout` қалады. Қалғаны (`register`, `account`, `nda`, `matching`, `kpi`, `dataroom/*`, `reports/*`, `forms/investor|project|membership`) жабық. Жоба каталогы Payload REST арқылы да жария көрінбейді (`projects` оқуы тек қызметкерге).

**Мәзір, футер, бургер, мазмұн:** инвесторлар мен жобалар бөлімі, «Нәтижелер», мүшелік өтініші мен тізілімі мәзірден алынады; «Өтініш беру» мен «Жеке кабинет» орнына бір «Байланысу» түймесі; футерде инвестор/мүше бағандары орнына «Қызметтер» және «Медиа». Беттердің карточкалары, сілтеме тізімдері және соңындағы шақырулар жасырын бетке апарса, көрсетілмейді (`visibleHref`). `sitemap.xml` жасырын жолдар мен жобаларды қамтымайды.

**Басты бет:** аудитория карточкалары, нәтиже ашықтығы, өмірлік цикл, жобалар қоры, дәліздер, бағалау, мүшелік блоктары жоқ, олардың деректері оқылмайды.

**Әкімші панелі** (`admin.hidden`, дерекқорда қалады): Scorecards, Investors, Matches, Ndas, DataroomFiles, DataroomLog, CoiDeclarations, Organizations, Registry (Agreements, Members, Issues), Projects, Users (портал қолданушылары), KPI басқару дашборды, `scoringConfig`, `kpiTargets`. «Басты бет» глобалында инвестициялық қойындылар да жасырын.

## 3. Corporate режимінде не қалады

Басты бет, қауымдастық туралы, басшылық (Zh фотосымен), қызметтер, жаңалықтар, іс-шаралар, серіктестер, құжаттар, фото және бейне, ішкі беттер (құқықтық, мүшелік туралы ақпарат), байланыс формасы (ALTCHA), төрт тіл, телефон нұсқасы, бургер мәзір, SEO.

**Басты бет құрамы:** hero, қауымдастық туралы, қызметтер, жаңалықтар, серіктестер, басшылық, байланыс. «Қауымдастық туралы» бөлімі `/about` бетінің сипаттамасы мен `/about/mission` бетінің қағидаттарынан құралады (админкада Беттер ішінде өзгертіледі). «Серіктестер» Серіктестер жинағынан (бос болса, серіктестікке шақыру карточкасы). «Байланыс» Баптаулардан (телефон, WeChat, пошта, мекенжайлар). Hero батырмалары: Басты бет глобалындағы сілтеме көрінетін бетке апарса, сол; әйтпесе «Қызметтеріміз» және «Байланысу».

**Әкімші панелі** төрт қазақша топқа бөлінген:
- **Мазмұн:** Беттер, Жаңалықтар, Іс-шаралар, Қызметтер, Серіктестер, Тұлғалар (басшылық), Құжаттар, Басты бет.
- **Медиа:** Фотоальбомдар, Бейнелер, Медиафайлдар.
- **Өтініштер:** байланыс өтініштері.
- **Жүйе:** Әкімшілер, Аудит журналы (тек рұқсаты бар рөлдерге), Баптаулар.

Әкімші `/admin` бетінде email және құпия сөзбен кіреді; өндірісте 2FA міндетті (`ADMIN_2FA` әдепкіде `on`). 2FA қосу/растау беті `/{тіл}/account/2fa` ашық қалады, бірақ corporate режимінде тек әкімші сессиясына (сессиясыз `/admin`-ге бағыттайды). «Аударма жоқ» белгісі бұрынғыдай.

## 4. Режимді кодта қалай басқарады

- Жасырын жолдар тізімі: `src/lib/mode.ts` (`hiddenSections`, `hiddenPages`, `alwaysOpen`, `openPortalApi`). Жаңа инвестициялық бет қосылса, осы тізімге қосып, `tests/unit/mode.test.ts` жаңартыңыз.
- Админка: `src/lib/admin-nav.ts` (`adminGroups`, `hiddenInCorporate`, көрінетін/жасырын жинақ тізімі). Жаңа жинақ қосылса, `tests/unit/corporate-admin.test.ts` оны көрінетін немесе жасырын тізімге қосуды талап етеді.
- Режимді тек `src/lib/mode.ts` оқиды. Басқа файл `process.env.PORTAL_MODE` оқымайды.

## 5. full-v1 нұсқасына қалай қайту

Үш жол, ең оңайынан бастап:
1. Бір кодпен: `PORTAL_MODE=full` қойып, серверді қайта іске қосыңыз. Бұл `full-v1` нұсқасының мінез-құлқын қайтарады (`npm run dev:full`, `npm run test:e2e:full` өтеді).
2. Дәл бұрынғы код: `git switch night-build` немесе `git checkout full-v1` (тег `corporate-lite` ашылар алдындағы күйді белгілейді).
3. Corporate-ті қайтару: `git switch corporate-lite`.

`full-v1` тегі мен `corporate-lite` тармағын GitHub-қа жіберу: `git push origin full-v1` және `git push -u origin corporate-lite`. HTTP 408 шықса, commit-терді біртіндеп жіберіңіз: `git push origin <commit>:refs/heads/corporate-lite` (ескіден жаңаға қарай), содан кейін `git push -u origin corporate-lite`.

## 6. Тесттер

| Команда | Не тексереді |
| --- | --- |
| `npm test` | Vitest: режимді оқу, жасырын жолдар (`mode.test.ts`), админка құрылымы (`corporate-admin.test.ts`), 4 тілдегі хабарламалар, қалғаны. Режимге тәуелсіз. |
| `npm run test:e2e` | Corporate: `corporate.spec.ts` (жасырын маршруттар 404, API жабық, жасырын сілтеме жоқ, 4 тіл, 1440 және 390 px, бургер мәзір, байланыс формасы, админка төрт тобы) және режимге тәуелсіз `stage0/1/3/4`. |
| `npm run test:e2e:full` | Full: бұрынғы барлық спек (`stage0-8`). |

Серверді басқа режимде іске қосып тест жүргізсе, `tests/e2e/global-setup.ts` бірден түсінікті қате береді (`/api/portal/kpi` жауабы бойынша режимді анықтайды).

- [ ] Мәзірде «Инвесторларға», «Жобалар», «Жеке кабинет», «Өтініш беру» жоқ; бір «Байланысу» түймесі.
- [ ] `/kk/projects`, `/kk/investors`, `/kk/account`, `/kk/results`, `/kk/membership/apply`: 404.

- [ ] `/admin`: төрт топ (Мазмұн, Медиа, Өтініштер, Жүйе), инвестициялық бөлімдер жоқ.
- [ ] `PORTAL_MODE=full`: бәрі бұрынғыдай (кабинет, жобалар, KPI дашборды).
