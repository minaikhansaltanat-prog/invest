# Түнгі тапсырма: порталды автономды құру

Сен осы жобаның жетекші әзірлеушісісің. Тапсырыс беруші ұйықтап жатыр және таңға дейін жауап бермейді. Сұрақ қоймай, тоқтамай жұмыс істе.

## 0. Түнгі режим ережесі
CLAUDE.md-дегі «алдымен жоспар ұсын, бекітілгеннен кейін ғана код жаз» ережесі бұл жолы қолданылмайды. Жоспарды `docs/PROGRESS.md` файлына жаз да, бірден орында. Күмән туса, ең ақылға қонымды шешімді таңда және `docs/PROGRESS.md` ішіндегі «Болжамдар» тізіміне жаз. Тек бір жағдайда тоқта: қайтарылмайтын әрекет керек болса (өндірістік серверге шығару, құпия кілт, төлемді сервис). Ондай әрекетті жасама, тізімге жаз да, келесі тапсырмаға көш.

## 1. Бастау
1. Оқы: `CLAUDE.md`, `docs/TZ.md` (1, 6, 11, 12, 13, 18, 19, 20 бөлімдер), `design/index.html`, `design/mockups/*`.
2. `git init` (егер git жоқ болса), `night-build` атты ветка аш. `main` тармағына тиме, push жасама.
3. `docs/PROGRESS.md` жаса: кезеңдер тізімі, әр кезеңнің күйі (күтуде / жұмыста / дайын / бөгелді), Болжамдар, Бөгелген тапсырмалар. Әр кезең соңында жаңарт. Контекст қысылып кетсе, жұмысты осы файлдан жалғастыр.

## 2. Кезеңдер
ТТ 18.2 кестесіндегі 0-10 кезеңдерді тәртіппен орында. Басымдық: ТТ 19-бөлімдегі R0, R1, R2 деңгейіне кіретін кезеңдер міндетті, қалғаны уақыт қалса. Әр кезеңнің соңында:
- `npm run lint && npm run typecheck && npm test` өтуі тиіс;
- кезеңнің Playwright тексеруі (1440 px және 390 px скриншот, `docs/screens/` папкасына);
- commit: `stage-N: қысқа сипаттама`;
- `docs/PROGRESS.md` жаңарту.
Бір мәселеде 3 әрекеттен кейін өтпесе, оны «Бөгелген» тізіміне жаз (қате мәтінімен) және келесі тәуелсіз кезеңге көш. Docker жұмыс істемесе, соған тәуелсіз бөліктерді (интерфейс, лингвистика, дизайн) жалғастыр.

## 3. Міндетті талаптар (ұмытуға болмайды)

### 3.1. Негізатушының фотосы «Zh»
- Жоба папкасынан атауы `Zh` деп басталатын сурет файлын тап: `find . -iname 'zh.*' -not -path './node_modules/*' -not -path './.git/*'`. Кеңейтімі кез келген болуы мүмкін (jpg, jpeg, png, webp, heic).
- Түпнұсқаны өзгертпе және өшірме. Көшірмесін `public/team/` ішіне ал, `next/image` арқылы AVIF/WebP, бірнеше өлшем, 4:5 қатынасымен көрсет.
- Басты беттегі басшылық карточкасында `ҒЖ` монограммасын осы фотомен ауыстыр (Ғалым Жанар, негізатушы).
- Payload-та басшылық коллекциясында фото өрісі, 4 тілдегі `alt`, «фотоны жариялауға келісім» (consent) өрісі болсын.
- Файл табылмаса, монограмманы қалдыр және `docs/PROGRESS.md` ішіне «Zh фотосы табылмады» деп жаз.

### 3.2. Телефон нұсқасы (адаптация)
- Тоқтау нүктелері: 360, 390, 768, 1080, 1440 px. Көлденең айналдыру (horizontal scroll) болмауы тиіс.
- Басылатын элемент кемінде 44x44 px. Мәтін 16 px-тен кем емес. Суреттерге `sizes` және lazy loading.
- Дизайн эталоны: `design/mockups/KFCA_basty_bet_mobile.jpg` және `design/index.html` ішіндегі 760 px макеті.
- Playwright: 360, 390, 768 px скриншоттары, көлденең айналдыру жоқтығын тексеретін тест.

### 3.3. Бургер мәзір және жабу түймесі (X)
- 1080 px-тен төмен `nav.menu` жасырылады, үш сызықты бургер-түйме көрінеді.
- Түйме басылғанда толық экранды панель ашылады (фон #071631, жылдам анимация, `prefers-reduced-motion` ескерілсін). Панель ішінде: негізгі мәзір (ішкі бөлімдер аккордеонмен), тіл ауыстырғыш (KK, RU, EN, 中文), негізгі әрекет түймелері.
- Панельдің жоғарғы оң жағында X түймесі (кемінде 44x44 px). Бургер-түйме ашық кезде өзі де X-ке айналсын.
- Жабылу жолдары: X түймесі, Esc, мәзір сілтемесін басу, артқы фонды басу, бетті ауыстыру.
- Қолжетімділік: `aria-expanded`, `aria-controls`, 4 тілдегі `aria-label` («Мәзірді ашу» / «Мәзірді жабу» және аудармалары), ашық кезде фокус панельде қалады (focus trap), жабылғанда фокус бургер-түймеге оралады, ашық кезде фон `inert`, бет айналдыру құлыпталады.
- Playwright тесті (390 px): ашу, X-пен жабу, Esc-пен жабу, фокус тұзағы, тіл ауыстыру.

### 3.4. Төрт тіл: kk, ru, en, zh (бастапқыдан міндетті)
- Сайттың барлық беттері мен әкімшілік панелі төрт тілде жұмыс істеуі тиіс: қазақша (әдепкі), орысша, ағылшынша, қытайша (zh-CN). Тілді «кейін қосамын» деп қалдырма: 0-кезеңнен бастап төртеуі бірдей құрылсын.
- URL: `/kk`, `/ru`, `/en`, `/zh`. Әр бетке `hreflang` және `alternate` сілтемелері. Тіл таңдауы cookie-де сақталсын, бірақ адрес бойынша тіл анық болсын.
- Интерфейс мәтіндері `messages/kk.json`, `ru.json`, `en.json`, `zh.json`: төрт файлда кілттер бірдей болуы тиіс. Мұны тексеретін Vitest тесті жаз (кілт жетіспесе тест құлайды).
- Контент Payload localization арқылы төрт тілде. Аударма жоқ жерде қазақша мәтін fallback болып көрінбесін: бос өрісті әкімшілік панелде «аударма жоқ» деп белгіле.
- zh үшін Noto Serif SC / Noto Sans SC self-host (Google Fonts жоқ), жол биіктігі мен әріп аралығы қытай мәтініне лайықталсын.
- Аудармаларды өзің жаз, бірақ әр аударма файлының басына `docs/PROGRESS.md`-де «аударма жобасы, тілші тексеруі қажет» деп белгіле. Қытайша мен қазақша мәтінді ана тілді адам тексеруі керек: ТТ-дағы қытай/қазақ ақпараттарын (серіктестің материалдары) негізге ал.
- Playwright: төрт тілде басты бет скриншоты (1440 және 390 px), тіл ауыстырғыш тесті.

### 3.5. Басқа қатаң ережелер
- Қазақ мәтінінде ұзын сызықша (em dash, U+2014) жоқ. Тексер: `grep -rnP "\x{2014}" messages content` бос болуы керек.
- Google Fonts, Maps, reCAPTCHA, YouTube жоқ. Қаріптер `public/fonts`-та.
- `.env` файлына тиме, құпия кілт жазба. Тек `.env.example`.
- Өндірістік серверге шығару (deploy) жоқ. Жаһандық пакеттерді орнатпа. Жоба папкасынан тыс файлға тиме.
- Тексерілмеген жоба ашық каталогқа шықпайды. Төрт сома өрісі ешқашан қосылмайды. Деректер бөлмесі тек NDA-дан кейін.

## 4. Таңертеңгі тапсырма
Жұмыс аяқталғанда немесе тоқтатуға мәжбүр болғанда `docs/MORNING.md` жаз:
1. Не дайын (кезеңдер бойынша), не дайын емес және неге.
2. Іске қосу: 3-4 команда (`docker compose up -d`, `npm install`, `npm run dev`, адрестер).
3. Шешім күтетін мәселелер (Болжамдар тізімі).
4. Қабылдау тексеру-парағы: басты бет 1440 px және 390 px, бургер мәзір, Zh фотосы, 4 тіл, /admin кіру, lint/typecheck/test нәтижесі.
5. Белгілі қателер.
Соңғы commit жасап, `git log --oneline` нәтижесін `MORNING.md` соңына қос.
