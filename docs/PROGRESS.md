## Жоспар (қысқаша шешімдер)

- Стек: Next.js 16 (App Router) + Payload 3.93 + PostgreSQL, Tailwind v4, next-intl 4, TypeScript strict, Vitest, Playwright.
- Түбір: `kfca-portal/` (репозиторий). Басты бет мәтіндері Payload `home` global-ынан, интерфейс мәтіндері `messages/*.json`-нан, бастапқы контент `content/seed/*` ішінен егіледі (seed).
- Docker жоқ болғандықтан әзірлеу базасы: embedded Postgres (`npm run db:dev`), өндіріс жолы: `docker-compose.yml`.
- Дизайн: эталон құрылымы мен токендер сақталады, бірақ шеберлік деңгейі көтеріледі (қозғалыс, текстура, көлеңке қабаттары, ою-өрнек, микро-әрекеттер). Тек `transform` мен `opacity` анимацияланады.
- Әр кезең соңында: lint + typecheck + test, Playwright скриншоты (`docs/screens/`), commit `stage-N: ...`, осы файлды жаңарту.

## Болжамдар (шешім күтеді)

1. **Жоба түбірі.** Жұмыс папкасы `Portal/`, репозиторий түбірі `kfca-portal/` (ТТ 13.2). `ZH.jpeg` ата-папкада (`Portal/ZH.jpeg`) табылды, ол тек оқылды, түпнұсқа өзгертілмеді.
2. **main тармағы.** Репозиторий бос болды, сондықтан `git init -b night-build` жасалды. `main` жасалған жоқ: таңертең өзіңіз қосасыз.
3. **Docker жоқ.** Бұл компьютерде Docker мен Postgres табылмады. Әзірлеу үшін npm-дағы `embedded-postgres` қолданылады. `docker-compose.yml` өндіріс жолына дайындалады, бірақ түнде іске қосылып тексерілген жоқ.
4. **Дизайн қайшылығы.** `Portal/CLAUDE.md` «эталонды жақсартпа» дейді, ал соңғы нұсқау дизайнды берілгеннен жоғары деңгейге шығаруды сұрады. Соңғы нұсқау басым: құрылым, мәтін, токендер, бөлімдер реті эталондағыдай, ал орындау сапасы (детальдар, қозғалыс, текстура) көтеріледі.
5. **Аударма саясаты.** ТТ 11.2 бойынша бекітілмеген аударма тізімнен жасырылады. Түнгі аудармалар жобалама, сондықтан `settings.translationPolicy` қосылды: `allow-draft` (іске қосуға дейін) және `approved-only` (іске қосқанда). Қазақша мәтін басқа тілде ешқашан fallback болып көрінбейді.
6. **Zh фотосына келісім.** Фото клиенттің NIGHT_TASK нұсқауымен берілді, сондықтан seed-те `consent = true`, себебі «клиент нұсқауы» деп жазылады. Жазбаша келісім файлын тіркеу керек. `consent = false` болса, сайт монограмманы көрсетеді.
7. **Zh фотосының кадры.** Түпнұсқа ақ үстелдегі басылған фото. Түпнұсқа көшірмесі сақталады, ал беттегі 4:5 кадр сол көшірмеден қиып алынған туынды файл.
8. **TypeScript нұсқасы.** npm-да TypeScript 7 шықты, бірақ Next/Payload құралдарымен үйлесімі белгісіз, сондықтан 5.x тұрақты нұсқа бекітілді.
9. **Компьютердегі PostgreSQL 16.** Бұл компьютерде 5432 портында жүйелік `postgresql-x64-16` қызметі жұмыс істейді (сіздің өз серверіңіз). Оған тиілген жоқ, құпия сөз болжанған жоқ. Әзірлеу базасы өз бинарларымен 54329 портында іске қосылады, ал `docker-compose.yml` хост порты 5433.
10. **Жолдағы қазақ әріптері.** Жоба папкасының атауында (`Жанар апай Қауымдастық`) Windows ANSI кодтауына сыймайтын қазақ әріптері бар. Нәтижесінде native `initdb.exe` жолды оқи алмайды. `scripts/db.mjs` барлық жолды 8.3 қысқа ASCII атауына (`D5B9~1`) ауыстырып шешеді. Сондай-ақ `npm install` осы жолда бір рет тұрып қалды, сондықтан `node_modules` ASCII жолында (`C:\tmp\kfca-npm-test`) орнатылып, көшірілді. Таңертең `npm install` тұрып қалса, жобаны ASCII жолына (мысалы, `C:\work\kfca-portal`) көшіріңіз.
11. **Node нұсқасы.** Payload 3.93 `node ^22.23.4 || >=24.22.1` талап етеді, ал мұнда 24.17.0 (тек ескерту, жұмысқа кедергі болған жоқ).
12. **Playwright браузері.** Playwright-тың өз Chromium-ы жүктелген жоқ: Windows-та жүйедегі Edge қолданылады (`channel: msedge`).
13. **Дизайн жақсартулары (басты бет).** Құрылым мен мәтін эталондағыдай, ал орындау сапасы көтерілді: қабатты нави көлеңкелер, SVG түйіршік, ою-өрнек, hero мәтінінің кезекпен шығуы, айналдырғанда пайда болу, санның өсуі, карточка hover-і (тек transform/opacity), ашылатын мәзір, eyebrow алдындағы алтын сызық, дәйексөздің алтын тырнақшасы, футердегі алтын сызық, қараңғы фондағы логотип ақ плашкада.
14. **Көрсетілетін контент егілген (seed).** `npm run seed` (дерекқор жұмыс істеп тұрғанда) 4 тілде басты бет, баптаулар, KPI, бағалау салмақтары, 8 қызмет, 3 мысал жоба, 4 мысал жаңалық және тұлғаны жазады. Жобалар мен жаңалықтар `isSample = true`: «Мысал ретінде көрсетілген» белгісімен.
15. **Eyebrow түсі.** Ашық фонда gold-700 (WCAG AA 4.5:1), эталондағы gold-500 (2.6:1) қолданылмады, орнына алдына gold-500 сызық қойылды. Hero-да (қараңғы фон) эталондағыдай gold-500.
16. **Күн форматы.** Қазақша Intl форматы жылдан басталатындықтан, күн-ай-жыл ретімен қолмен құрылады: 28 қазан 2026, 28 октября 2026, 28 October 2026, 2026年10月28日.
17. **Күтпеген e2e ақаулары.** Агенттер файл жазғанда dev сервер бетті қайта жүктейді, сондықтан бірнеше көлденең айналдыру тесті кездейсоқ құлауы мүмкін (қайта іске қосқанда өтеді).
18. **Әкімшілік панелінің қазақша интерфейсі.** Payload-та қазақ тілі жоқ. `src/i18n/admin-kk.ts` орыс аудармасының негізінде ең көп көрінетін жолдарды қазақшаға ауыстырады (аударылмаған кілт орысша қалады). Бұл түнгі жоба: ана тілді тілші тексеруі қажет. Payload `Accept-Language` ішінде тек өз тізіміндегі тілдерді таниды, сондықтан әдепкі тіл `kk` қойылды: ru/en/zh браузері өз тілін алады, қалғаны қазақша көреді; тілді «Аккаунт» бетінде ауыстыруға болады.
19. **«Аударма жоқ» белгісі.** Тілге бөлінген мәтін/textarea өрісі қазақшадан басқа тілде бос болса, админкада алтын «Аударма жоқ (RU)» белгісі шығады. Rich text және басқа өріс түрлері үшін белгі жоқ (бұл өрістер үшін `translationStatus` пен деректер қабаты жасырады).
20. **Аудармасы жоқ бет.** Тіл ауыстырғанда жазбаның аудармасы жоқ болса, `redirectMissingTranslation()` тізім бетіне `?notice=no-translation` параметрімен бағыттайды, `TranslationNotice` хабарламаны (toast) көрсетіп, параметрді URL-дан алып тастайды. Көмекші детальді беттерге 5-кезеңде қосылады.
21. **Жұмыс уақыты сидте жоқ.** ТТ-да жұмыс уақыты көрсетілмеген. Бұрын сидте «Дс-Жм 09:00-18:00» тұрған, ол бекітілмеген дерек болғандықтан алынып тасталды; әкімші `settings.workingHours` өрісін админкада толтырады. Байланыс беті «бекітілгеннен кейін жарияланады» деп жазады. Орысша мекенжайдағы қазақ әрпі (`Әнет` → `Анет`) түзетілді.

22. **Ішкі беттер Payload блоктарымен.** `pages` жинағы 8 блок түрінен жиналады (абзац, карточка, қадам, факт, FAQ, кесте, ескертпе, сілтеме) және соңғы CTA. 38 бет пен 8 қызметтің толық мазмұны `content/seed/pages/*` ішінде 4 тілде, `npm run seed` дерекқорға егеді. Қатар id-лері тұрақты, сондықтан қайта егу қатарларды көбейтпейді. Барлық аударма жобалама (`draft`).
23. **Бейне, серіктес, іс-шара.** Бейне YouTube-сыз, тек өз серверіндегі mp4. Серіктес логотипі `showLogo` қолмен қойылғанда ғана шығады (жазбаша рұқсат). Іс-шара, бейне, фотоальбом, серіктес, құжат үшін шынайы материал жоқ болғандықтан сид жасалмады: беттерде бос күй көрсетіледі, әкімші админкада толтырады.
24. **ТТ-да дерегі жоқ орындар бейтарап жазылды.** Мерзімдер, жарна мөлшері, байланыс поштасы, жұмыс уақыты, басқару органдарының нақты өкілеттіктері, сыбайлас жемқорлыққа қарсы тәртіптің толық мәтіні, дерек сақтау мерзімі, серіктес пен мүшелердің аттары, нәтиже сандары: бетте «бекітілгеннен кейін жарияланады» деп жазылған. Тізімі `docs/MORNING.md` ішінде.
25. **Жариялау ағыны тесті.** `tests/e2e/stage4.spec.ts` уақытша әкімші тіркейді (`first-register`), бетті жобалама → жарияланды → жобалама күйлерінен өткізіп, соңында бетті де, әкімшіні де жояды (дерекқор «бірінші әкімші» күйінде қалады). Әкімші бар болса, бұл тест өткізіліп жіберіледі.

26. **Ішкі беттердің жалпы құрылымы.** Барлық 38 бет бір catch-all маршрутпен (`[...slug]`) ашылады: Payload `pages` блоктары, оң жақ мазмұн тізімі (TOC, ≥1080 px), соңғы CTA. Динамикалық тізімдер (қызметтер, жобалар каталогы, жаңалықтар, іс-шаралар, бейне, фото, серіктестер, басшылық, құжаттар) блоктардан кейін шығады, дерек жоқ болса бос күй. Егжей-тегжейлі беттер: қызмет, жоба, жаңалық, фотоальбом. Аудармасы жоқ жазба тізім бетіне хабарламамен бағытталады.
27. **Жоба беті ашық бөлікпен шектеледі.** Каталогта тек 2-3 деңгейлі, жариялауға рұқсат берілген жоба көрінеді (`access` функциясы). Жоба бетінде қысқа сипаттама мен негізгі деректер ғана, толық паспорт пен деректер бөлмесі NDA-дан кейін (7-кезең) деген ескерту.
28. **Tailwind брейкпоинттері.** Жобада `xs 390, md 768, lg 1080, xl 1440` ғана бар (`sm` жоқ). `sm:` кластары үнсіз жұмыс істемейді, сондықтан жаңа кодта тек осы төртеуі қолданылады.
29. **Dev режимінің 404 ескертуі.** Next dev режимінде 404 бетінде React «script tag» ескертуін береді (layout ішіндегі reveal скрипті). Тек dev, өндірісте жоқ; бет жұмысына әсері жоқ.
30. **ALTCHA сыртқы пакетсіз.** `altcha` пакеті орнатылмаған (npm бұл жолда тұрып қалады, жаңа пакет қосылмады). Сондықтан ALTCHA хаттамасымен үйлесімді proof-of-work өзіміз жазылды (`src/lib/security/altcha*.ts`): HMAC қол қойылған challenge, мерзімі, replay қорғанысы, Web Crypto шешуші. Google reCAPTCHA жоқ.
31. **2FA (TOTP).** RFC 6238 Node crypto-мен жазылған (тест RFC векторларымен), QR суреті жоқ: кілт пен otpauth сілтемесі көрсетіледі (QR-кітапхана орнатылмаған). Кілт базада AES-256-GCM-мен шифрланған. Инвесторда 2FA қосылса, Payload-тың өз `/api/users/login` жолы да кодсыз сессия бермейді. Деректер бөлмесі 2FA-ны талап етеді (7-кезең).
32. **Әкімші 2FA қақпасы.** `kfca-2fa` қолтаңбалы cookie TOTP расталғанын білдіреді; `proxy.ts` әкімші панелін, ал `isAdminUser` барлық API құқығын осыған байлайды. Өндірісте әдепкіде міндетті, әзірлеуде әдейі өшірулі (`ADMIN_2FA=on` қосады), себебі Payload-тың кіру формасы код өрісін жібере алмайды және тесттер жеңіл болуы тиіс. Таңертең тексеру: `.env` ішіне `ADMIN_2FA=on`, кіргеннен кейін `/kk/account/2fa` бетінде 2FA қосыңыз.
33. **Хат жіберу.** SMTP адаптері (`@payloadcms/email-nodemailer`) орнатылмаған, сондықтан хаттар Payload консоліне жазылады; өтініш әкімшілік панельдегі «Өтініштер» бөлімінде сақталады. Өндіріс үшін адаптер мен `SMTP_*`, `NOTIFY_EMAILS` қажет. Құпия сөзді қалпына келтіру мен пошта растау (email verification) осы себепті жасалған жоқ.
34. **Rate limit жад ішінде.** Формалар, тіркелу, TOTP, ALTCHA үшін шектеу бір процесс жадында (`src/lib/security/rateLimit.ts`). Көп инстансты өндіріс үшін Redis/PG негізді шектеу 9-кезеңде. Тест ортасында `x-test-client-ip` тақырыбы IP-ді модельдейді (өндірісте ескерілмейді).
35. **Hook ішіндегі Local API.** Payload hook ішінде Local API шақыруына `req` беру міндетті: әйтпесе бөлек қосылым кіру транзакциясы ұстаған жолды күтіп, deadlock болады (кіру беті тұрып қалады). Бұл `recordLogin` ішінде түзетілді және ережеге айналды.
36. **Кабинет.** Қазір: тіркелу, кіру, өтініш мәртебелері, 2FA, кіру тарихы, деректерді JSON ретінде жүктеу, жою сұранысы. Инвестор мен жоба иесінің арнайы бөлімдері (ұсынылған жобалар, NDA, деректер бөлмесі) 7-кезеңде қосылады.

## Аударма жобасы ескертпесі

`messages/*.json` және `content/seed/*` ішіндегі барлық аудармаларды (ru, en, zh және қазақ мәтіндері) түнде Claude жазды. Бұл аударма жобасы: ана тілді тілші тексеруі қажет, әсіресе қытайша және қазақша мәтіндер. Қытайша мәтіндер ТТ-дағы серіктес материалдарының терминологиясына сүйенді.
